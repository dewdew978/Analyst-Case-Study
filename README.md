# FruitBlend24 — วิเคราะห์ยอดขายและกำไร

งานนี้ใช้ข้อมูลยอดขายตั้งแต่ ก.ย. 2025 ถึง ส.ค. 2026 มาดูว่าเมนูไหนขายดี ราคาและโปรที่ใช้อยู่ยังเหลือกำไรหรือไม่ ครัวไหนควรแก้ไข และควรเตรียมวัตถุดิบเท่าไรใน 3 เดือนถัดไป ข้อมูลเป็นชุดจำลองสำหรับแบบทดสอบ ตัวเลขเงินทั้งหมดเป็นบาท

ใช้ `analysis.ipynb` คลีนข้อมูลจาก Excel แล้วเก็บเป็น CSV ใน `cleaned_data/` จากนั้นส่วนวิเคราะห์อ่าน CSV ชุดนี้มาคำนวณ และบันทึกผลสรุปลง `app_data/` ให้ Streamlit แสดงเป็นกราฟและตาราง

## เปิดใช้งาน

1. เปิด Terminal ในโฟลเดอร์งาน แล้วติดตั้งแพ็กเกจด้วย `python -m pip install -r requirements.txt`
2. เปิด `analysis.ipynb` แล้วกด **Run All**
3. เปิดแอปด้วย `python -m streamlit run app.py`

ครั้งแรกให้ Run All เพื่อสร้างทั้งข้อมูลที่คลีนแล้วและผลสรุป ลำดับคือ **Excel → cleaned_data → วิเคราะห์ → app_data → Streamlit**

เมื่อมี CSV ใน `cleaned_data/` ครบแล้ว สามารถ Restart Kernel และเริ่มรันจากหัวข้อ 2 ได้ ส่วนนี้จะอ่านจาก CSV โดยไม่ต้องเปิด Excel หรือคลีนซ้ำ ถ้าข้อมูลต้นฉบับหรือวิธีคลีนเปลี่ยน ให้ Run All ใหม่ หากแก้เฉพาะวิธีวิเคราะห์ให้รันจากหัวข้อ 2 แล้วรีเฟรชแอป

## 1. เตรียมข้อมูลก่อนวิเคราะห์

ข้อมูลดิบมี 124,397 แถว พบแถวที่ทุกคอลัมน์เหมือนกัน 372 แถว จึงเก็บไว้เพียงหนึ่งแถวต่อชุดด้วย `drop_duplicates()` วิธีนี้ถือว่าแถวที่เหมือนกันเป็นการบันทึกซ้ำ แต่ยังยืนยันจากรหัสรายการขายไม่ได้ เพราะข้อมูลไม่มีรหัสนี้ให้

ชื่อเมนูมีทั้งหมด 31 รูปแบบ เช่น ชื่อไทยกับอังกฤษ ตัวพิมพ์ใหญ่เล็ก และคำสะกดต่างกัน จึงปรับชื่อแล้วจับคู่เป็น 5 เมนูหลัก ส่วน Combo Set A, น้ำส้มปั่นเมนูทดลอง และแก้วเปล่า แยกออกไว้ต่างหาก รวม 370 แถว มูลค่า 38,478 บาท หลังจัดการเหลือ **123,655 แถว รายได้ 31,146,932.57 บาท** สำหรับการวิเคราะห์

ต้นทุน Mixed Berry วันเปิดขาย 1 มี.ค. 2026 ขาดอยู่สองส่วน จัดการดังนี้:

- ต้นทุนผลไม้ของยอดขาย 75 แถว ใช้ต้นทุนวันที่ 2 มี.ค. ซึ่งเป็นสัปดาห์แรกที่มีข้อมูล เท่ากับ 33.69 บาทต่อแก้ว
- ของเสีย 4 แถวมีจำนวนรวม 96 แก้ว แต่ไม่มีต้นทุน จึงคำนวณจาก 96 × (ผลไม้ 33.69 + แพ็กเกจ 8) ได้ 4,002.24 บาท

ทั้งสองส่วนระบุไว้ในคอลัมน์ `estimated_cost` เพื่อให้รู้ว่าเป็นค่าประมาณ

อีกปัญหาคือไม่มีบันทึกของเสีย 6 รายการ โดยแต่ละรายการคือหนึ่งวันที่ของครัวและเมนูนั้น ไม่ใช่ของเสีย 6 แก้ว จึงเติมจำนวนเสียจากค่ามัธยฐานของครัวและเมนูเดียวกัน ในวันเดียวกันของสัปดาห์ ช่วง 4 สัปดาห์ก่อนและหลังวันที่ขาด แต่ละรายการมีข้อมูลอ้างอิง 5–8 วัน

นำจำนวนที่ประมาณมาคูณต้นทุนผลไม้และแพ็กเกจของสัปดาห์ที่ขาด ปัดต้นทุนแต่ละรายการเป็นสตางค์แบบครึ่งขึ้น ได้ต้นทุนเพิ่มรวม **418.67 บาท** และรวมใน P&L แล้ว โดยระบุ `waste_estimated` พร้อมเก็บจำนวนเสีย ต้นทุน และจำนวนวันอ้างอิงไว้ใน Notebook และ CSV เพื่อให้ตรวจสอบได้ จำนวนที่ประมาณอาจเป็นเศษแก้ว เพราะเป็นค่าคาดหมาย ข้อมูลหลังวันที่ขาดใช้เติมประวัติย้อนหลังเท่านั้น ไม่ได้ใช้ในการทดสอบพยากรณ์ และควรแทนค่าประมาณด้วยบันทึกจริงเมื่อได้รับข้อมูล

## 2. ดูยอดขายและประเมินราคา

เริ่มจากรวมยอดขายรายวันแยกครัวและเมนู แล้วดูยอดเฉลี่ยต่อวันของแต่ละเดือน เพื่อให้เทียบเดือนที่มีจำนวนวันต่างกันได้ ส่วนยอดรายชั่วโมงใช้ข้อมูล 8 สัปดาห์ล่าสุด

ยอดขายช่วง มี.ค.–พ.ค. สูงกว่าช่วงท้ายข้อมูล จึงเลือกใช้ยอดช่วงล่าสุดในการวางแผนต่อไป สำหรับ Mixed Berry ที่เพิ่งเริ่มขายในเดือน มี.ค. จะดูทั้งยอดรวมและกำไรต่อแก้ว เพราะมีระยะเวลาขายสั้นกว่าเมนูอื่น

ใช้ต้นทุนเดือน ส.ค. ประเมินราคาปัจจุบัน ได้ผลดังนี้:

| เมนู | ราคาปกติ | กำไรต่อแก้วหลังคอมมิชชันและของเสีย | ราคาที่เสนอให้ทดลอง |
|---|---:|---:|---:|
| Watermelon | 45 | 12.60 | 50 |
| Pineapple | 49 | 13.04 | 55 |
| Guava | 49 | 12.27 | 55 |
| PassionFruit | 65 | 2.88 | 75 |
| MixedBerryPremium | 89 | -17.07 | 119 |

กำไรต่อแก้วเป็นค่าเฉลี่ยจากยอดขายจริงเดือน ส.ค. รวมทุกแพลตฟอร์มและโปร ยังไม่หักค่าใช้จ่ายประจำของครัว (overhead)

Mixed Berry ควรแก้ก่อน เพราะราคาปกติ 89 บาทยังต่ำกว่าราคาคุ้มทุนที่ประมาณได้ คือ 114.53 บาทบน LINE MAN และ 105.49 บาทบน Grab จึงเสนอให้ทดลองราคา 119 บาทพร้อมงดส่วนลด แล้วติดตามทั้งยอดขายและกำไรรวม

ราคาคุ้มทุนคำนวณจากต้นทุนผลไม้ แพ็กเกจ แรงงานผันแปร และของเสียเฉลี่ยต่อแก้ว หารด้วย `1 − อัตราคอมมิชชัน` โดยสมมติให้ต้นทุนของเสียต่อแก้วเท่ากันระหว่างแพลตฟอร์ม ราคานี้ยังไม่รวม overhead ส่วนราคาทดลองของทุกเมนูยังต้องวัดผลจริง

## 3. ดูว่าโปรไหนยังคุ้ม

แยก `rate_code` เพื่อดูแพลตฟอร์มและประเภทโปร แล้วสรุปจำนวนขาย รายได้ จำนวนวันที่ใช้ และกำไรต่อแก้วของแต่ละเมนู จากนั้นนำโปรมาคำนวณใหม่ด้วยต้นทุนเดือน ส.ค. เพื่อเทียบบนฐานเดียวกัน

LINE MAN คิดคอมมิชชัน 30% และ Grab 24% ส่วนราคาขายในข้อมูลหักส่วนลดมาแล้ว จึงใช้รายได้ที่บันทึกคำนวณผลจริงได้เลย

เมื่อประเมิน RC101, RC102 และ RC103 รวม 30 ชุดเมนู–แพลตฟอร์ม–โปร พบว่า **9 ชุดขาดทุนตั้งแต่ยังไม่รวมของเสีย** จึงเสนอให้พักหรือลดส่วนลดของกลุ่มนี้ ส่วนโปรที่ยังเหลือกำไรก่อนของเสียแต่ขาดทุนหลังของเสีย ควรปรับทั้งส่วนลดและปริมาณเตรียมสินค้า โดยมี RC000 เป็นราคาปกติอ้างอิง

ยอดรวมของแต่ละโปรยังบอกไม่ได้ว่าโปรช่วยเพิ่มยอดเท่าไร เพราะเกิดคนละช่วงและใช้จำนวนวันต่างกัน การตัดสินใจจึงดูจากกำไรต่อแก้วก่อน แล้วค่อยทดลองแบบมีกลุ่มเปรียบเทียบเพื่อวัดกำไรรวมที่เพิ่มขึ้น

## 4. ทำ P&L และหาครัวที่ควรแก้ไข

เนื่องจากไม่มี P&L มาให้ จึงรวมยอดขายและต้นทุนขึ้นใหม่เป็นรายเดือนแยกครัว แล้วรวมเป็นผลบริษัท โดยใช้ลำดับนี้:

- กำไรขั้นต้น (GP) = รายได้ − ผลไม้ที่ขาย − แพ็กเกจที่ขาย − แรงงานผันแปร
- กำไรส่วนเกิน (contribution) = GP − คอมมิชชัน − ต้นทุนของเสีย
- กำไรจากการดำเนินงาน = contribution − overhead

งบรายเดือนกำหนดรายได้ 2.7 ล้านบาท และ GP 700,000 บาท แต่ไม่ได้แจกแจงนิยาม GP ไว้ครบ จึงแสดงทั้ง GP และ contribution เทียบกับงบ GP ให้เห็นว่าต้นทุนที่หักต่างกันมีผลอย่างไร ส่วนต่างในตารางคำนวณจากผลจริงลบงบ ถ้าติดลบคือต่ำกว่าเป้า งบนี้เป็นระดับบริษัท จึงใช้ประเมินครัวจากกำไรจริงแทนการสร้างงบรายครัวขึ้นมา

ทั้งปีรายได้ต่ำกว่างบ **1,253,067.43 บาท** และขาดทุนจากการดำเนินงาน **403,649.69 บาท** โดยขาดทุน 8 จาก 12 เดือน ผลแต่ละครัวเป็นดังนี้:

| ครัว | กำไรจากการดำเนินงานทั้งปี |
|---|---:|
| BKK_Ladprao | -620,967.84 |
| BKK_Sukhumvit | -486,552.52 |
| Pattaya_Beach | 332,445.09 |
| Pattaya_Central | 371,425.58 |

ควรเริ่มทบทวนยอดขายและค่าใช้จ่ายของสองครัวกรุงเทพฯ โดยตั้งเป้าประหยัดครัวละ 15,000 บาทต่อเดือน แต่ต้องระบุให้ได้ว่าลดค่าใช้จ่ายรายการไหนได้จริงก่อนนำไปใช้

เมื่อดูรายเมนู Mixed Berry ขาดทุนหลังของเสีย 53,860.03 บาท ก่อน overhead จึงควรปรับราคา โปร และจำนวนเตรียมก่อน ส่วนค่าใช้จ่ายประจำยังไม่ได้แบ่งให้แต่ละเมนู เพราะไม่มีเกณฑ์จัดสรรในข้อมูล P&L รวมของเสียที่ประมาณทั้ง 6 รายการแล้ว ตัวเลขส่วนนี้อาจเปลี่ยนได้เมื่อได้รับบันทึกจริง

## 5. วางแผนขายและวัตถุดิบ 3 เดือน

พยากรณ์ ก.ย.–พ.ย. 2026 ด้วยยอดขายเฉลี่ยต่อวัน 28 วันล่าสุด แยกครัวและเมนู แล้วคูณจำนวนวันในแต่ละเดือน ใช้ต้นทุนและสัดส่วนแพลตฟอร์มเดือน ส.ค. คำนวณกำไรต่อ

ลองทดสอบย้อนหลังโดยใช้เฉพาะข้อมูลก่อนช่วงทดสอบ พบความคลาดเคลื่อน WAPE 14.29% สำหรับเดือน ส.ค. และ 52.22% เมื่อทำนาย มิ.ย.–ส.ค. รวดเดียว ค่านี้คิดจากผลรวมส่วนต่างสัมบูรณ์ของยอดรายวันแยกครัวและเมนู หารด้วยยอดจริงรวม ผลระยะ 3 เดือนคลาดเคลื่อนค่อนข้างมาก จึงควรอัปเดตแผนทุกสัปดาห์

ทำไว้สองกรณี คือใช้ราคาและอัตราของเสียเดิม กับทดลองปรับตามข้อเสนอ ในแผนทดลองสมมติว่า:

- ใช้ราคาทดลองในข้อ 2 โดยคงส่วนลดเดิมของ 4 เมนูแรก และงดส่วนลด Mixed Berry
- ยอดขาย 4 เมนูแรกลดลง 5% และ Mixed Berry ลดลง 20% หลังปรับราคา ตัวเลขนี้เป็นสมมติฐาน ยังไม่ได้วัดผลของราคาต่ออุปสงค์
- อัตราของเสียลดลงครึ่งหนึ่ง และสองครัวกรุงเทพฯ ประหยัดค่าใช้จ่ายรวม 30,000 บาทต่อเดือน

| กรณี | กำไรจากการดำเนินงานรวม 3 เดือน |
|---|---:|
| ใช้ราคาและอัตราของเสียเดิม | -766,640.79 |
| แผนทดลอง แต่ยังลด overhead ไม่ได้ | -58,396.20 |
| แผนทดลอง และลด overhead ได้ตามเป้า | 31,603.80 |

แผนนี้จะกลับมามีกำไรเมื่อทำเงื่อนไขได้ครบ จึงต้องติดตามผลจริงทั้งยอดขาย ของเสีย และค่าใช้จ่ายที่ลดได้

ด้านวัตถุดิบ คำนวณจำนวนเตรียมจาก `ยอดขายคาดการณ์ ÷ (1 − อัตราของเสีย)` โดยอัตราของเสียคิดจากจำนวนเสียหารด้วยจำนวนขายรวมจำนวนเสีย แล้วใช้แผนทดลองทำตารางจำนวนเตรียมและมูลค่าผลไม้รายเดือนแยกครัวและเมนู

ตัวอย่างการสั่งซื้อสมมติให้ส่งของใช้เวลา 1 วัน ทบทวนทุกวัน และสำรองอีกครึ่งวัน จึงตั้งเป้าสต็อกประมาณ 2.5 วัน ปัดจำนวนขึ้น แล้วหักของที่ใช้ได้และของที่กำลังรับ หากผลติดลบให้สั่งเป็นศูนย์ ควรแบ่งรับและเตรียมเป็นรอบ พร้อมใช้ของที่ใกล้หมดอายุก่อน (FEFO)

ในตารางตั้งของใช้ได้และของกำลังรับไว้ที่ 0 เพื่อเป็นตัวอย่าง ต้องกรอกยอดจริงก่อนสั่ง อายุวัตถุดิบ 3 วันก็เป็นสมมติฐานที่ต้องยืนยัน ส่วนปริมาณยังเป็นแก้วเทียบเท่าวัตถุดิบ ต้องมีสูตรต่อแก้วก่อนแปลงเป็นกิโลกรัม

## 6. ดูผลใน Streamlit

แอปแบ่งเป็น 3 แท็บ:

- **ภาพรวม** ดูรายได้ กำไร เทียบงบ ผลแต่ละครัว และปัญหาข้อมูล
- **เมนูและโปรโมชัน** ดูแนวโน้มยอดขาย เลือกเมนูเพื่อดูราคาคุ้มทุนและโปรที่ควรปรับ
- **พยากรณ์และวัตถุดิบ** เทียบแผน 3 เดือน ดูจำนวนเตรียมและเป้าสต็อก

ประเด็นหลักที่ใช้ตัดสินใจมี 5 เรื่อง คือบริษัทยังขาดทุนแม้มีรายได้, Ladprao ขาดทุนสูงสุด, Mixed Berry ขาดทุนหลังของเสีย, โปรบางกลุ่มขายแล้วไม่พอต้นทุน และแผน 3 เดือนยังต้องพึ่งทั้งการปรับราคา ลดของเสีย และลดค่าใช้จ่าย ข้อเสนอจึงเริ่มจากทดลองราคาและปรับโปร ทบทวนสองครัวกรุงเทพฯ และเติมวัตถุดิบตามยอดขายล่าสุด

## ไฟล์ในโครงการ

- `FruitBlend24_Intern_Case_Data.xlsx` เป็นข้อมูลต้นฉบับ
- `analysis.ipynb` หัวข้อ 1 เตรียมและบันทึกข้อมูล ส่วนหัวข้อ 2–6 อ่านข้อมูลที่คลีนแล้วมาวิเคราะห์
- `app.py` เป็นแอป Streamlit
- `cleaned_data/` เก็บข้อมูลระดับแถวและตารางอ้างอิงพร้อมวิเคราะห์
- `cleaned_data/review/` เก็บรายการที่แยกออกและรายละเอียดการประมาณ
- `app_data/` เก็บ CSV ผลสรุป 8 ไฟล์ที่ Streamlit ใช้
- `backups/` เก็บงานฉบับก่อนหน้า

ข้อมูลใน `cleaned_data/` มีดังนี้:

| ไฟล์ | ข้อมูลที่เก็บ |
|---|---|
| `orders_clean.csv` | ยอดขายครบ 123,655 แถว พร้อมชื่อเมนูมาตรฐาน ต้นทุน คอมมิชชัน และคอลัมน์ระบุค่าประมาณ |
| `waste_clean.csv` | ของเสียครบ 6,576 แถว รวม 6 รายการที่เติม พร้อมคอลัมน์ระบุค่าประมาณ |
| `weekly_fruit_cost.csv` | ต้นทุนผลไม้รายสัปดาห์ |
| `menu_costs.csv` | แพ็กเกจ แรงงานผันแปร และราคาปกติ แยก 5 เมนู |
| `kitchen_overhead.csv` | ค่าใช้จ่ายประจำรายเดือนของแต่ละครัว แยกจากชีตต้นทุนเดิม |
| `platform_commission_rate.csv` | อัตราคอมมิชชันแต่ละแพลตฟอร์ม |
| `rate_code_dim.csv` | รหัสโปร ส่วนลด และเงื่อนไข |
| `monthly_budget.csv` | งบรายเดือนของบริษัท |
| `platform_dim.csv`, `sku_code_dim.csv` | ตารางอ้างอิงแพลตฟอร์มและรหัสเมนู |

โฟลเดอร์ `review/` มีแถวซ้ำ 372 แถวใน `duplicates.csv`, รายการนอกขอบเขต 370 แถวใน `excluded_items.csv`, ของเสียที่เติม 6 รายการใน `waste_estimates.csv` และสรุปการคลีนใน `data_quality.csv` คอลัมน์ `source_index` ในสองไฟล์แรกคือตำแหน่งแถวเดิมใน DataFrame เริ่มนับจาก 0

ตารางต้นทุนและตารางอ้างอิงที่ไม่มีปัญหาเก็บค่าเดิมไว้ ส่วนชีต README และ data_dictionary ยังอยู่ใน Excel ต้นฉบับ จึงไม่ได้ทำสำเนาเป็น CSV เพิ่ม ไฟล์ต้นฉบับไม่ถูกแก้ทับ

ข้อมูลทั้งหมดเปิดดูใน Excel ได้ เมื่อ Run All จะสร้าง CSV ทั้งสองโฟลเดอร์ใหม่ จึงควรแก้ข้อมูลต้นทางหรือโค้ดแทนการแก้ผลลัพธ์ CSV โดยตรง ปัจจุบันแอปใช้งานบนเครื่อง ยังไม่ได้เผยแพร่สาธารณะ
